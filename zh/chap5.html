如上，如果你是这么想的，那么恭喜你，你重新造出了一个叫做二元线性回归的轮子。就像我们之前说的，不管你是t检验、方差分析、相关、还是回归方程，都可以以一种线性模型的视角思考。那么这个二元线性回归，除了比一元线性回归贵了一元之外，也可以视为和双因素方差分析在某种程度上等价。而遵循着一样的数数能力限制，三元以上的线性回归，我们叫它们多元线性回归模型。

如果你如我希望的，已经学过方差分析，你一定会知道一个词，叫做因素的主效应（main effect）。实际上上面的线性回归，就是对这两个变量或者我们叫因素的主效应的检验，也就是主效应模型。不过我们这么介绍有点鸡生蛋蛋生鸡的循环定义问题，所以主效应具体是什么呢？

用一样的逻辑，它似乎应该对应的是两个哑变量编码都对应参照水平的那个组，也就是都编码为0的那一组的均值。也就是武装直升机+无灵根那一组的均值。但是我们可以看到，上面模型里的截距数值是78.1812，而武装直升机+无灵根组的平均值是70.50922。数值上相差的很多。那么，亲爱的读者们，你们觉得是什么原因呢？是我们的逻辑发生了错误，还是它其实对应着其他的平均值？

好了，不为难大家了。其实我们不妨换一个角度考虑，如果找不到这个截距对应的平均数，也许并不是我们上面的推理出了问题，而是我们的模型本身出了问题？

我们之前介绍过一些简单回归或者单因素方差分析模型的统计假设。在多元回归，也就是像我们这样的多个预测变量的回归中，统计上还有一个假设，叫做加法假设（Additive assumption）3。什么意思呢，我们来看下面的公式。

\[ y=b_0+b_1x_1+b_2x_2+e \]

这是一个二元回归方程，我们上面的数据分析就可以写成这种形式，x1就是我们的性别自我认同，x2就是我们的灵根。如果我们的x1在数值上增加1呢？

\[ \tilde y=b_0+b_1(x_1+1)+b_2x_2+e \]

把式子展开，就可以看出：

\[ \begin{align} \tilde y&=b_0+b_1x_1+b_1+b_2x_2+e\\ \tilde y&=b_0+b_1x_1+b_2x_2+e+b_1\\ \tilde y&=y+b_1 \end{align} \]

换句话说，理论上来说，x1每增加一个单位，y最终的数值就会对应地增加x1对应的回归系数。符合直觉，对吧？

这时候，学过两因素以上方差分析的读者大概会一脸不屑。你写了这么久，说的这个现象不就是交互作用么。是的！如果你还记得我们这个小节的标题是什么的话，这就是我引入交互作用的方式。我想说的正是，加法假设的意思，其实就是变量之间不存在交互作用4。

\[ 魔法天赋分数=b_0+b_1性别自我认同+b_2灵根 \]

如果我们认为性别自我认同对于魔法天赋分数的影响在有灵根和无灵根时不一样，这意味着什么呢？我们前面说了，在线性模型中，我们把回归系数，也就是变量的斜率，看作是预测变量对于结果变量的影响程度。那么，当存在交互作用，或者加法假设被违反时，这意味着预测变量对于结果变量的影响，也就是斜率，受到另一个变量的影响。有灵根时，性别自我认同的斜率是一个值，没有灵根时又是另外一个值了。换句话说，在我们的例子里，性别自我认同对于魔法天赋分数的影响，也就是它的斜率，受到灵根的影响。是不是感觉我在说绕口令？没关系，我们可以用优美简洁的数学来表达这件事。我们上面式子中的b1代表性别自我认同对于魔法天赋的影响，那么，性别自我认同对于魔法天赋分数的斜率受灵根影响可以表达为：

\[ b_1=b_3+b_4灵根 \]

也就是说，b1是一个受灵根预测的结果变量。我们不妨把b1代回原来的式子，整理一下可以得到：

\[ \begin{align} 魔法天赋分数&=b_0+(b_3+b_4灵根)性别自我认同+b_2灵根\\ 魔法天赋分数&=b_0+b_3性别自我认同+b_4灵根\times 性别自我认同+b_2灵根 \end{align} \]

为了我们对回归系数的编码美观，我们可以调整一下回归系数的下标，写成：

\[ 魔法天赋分数=b_0+b_1性别自我认同+b_2灵根+b_3灵根\times 性别自我认同 \]

不难看出，这个式子也可以看作灵根对魔法天赋的影响（斜率）受性别自我认同的影响：

\[ 魔法天赋分数=b_0+b_1性别自我认同+(b_2+b_3性别自我认同)灵根 \]

这也是交互作用的意思，当两个预测变量存在交互作用时，它们对结果变量的影响是彼此互相作用的，也就是一个“交互”的作用。你可以看作是性别自我认同影响灵根对魔法天赋的影响，也可以看作是灵根影响自我性别认同对天赋的影响，这是一个一体两面的现象。

构建出了上面的式子，就不难看出，在方程中加入两个变量的乘积项，就是检验交互作用的方法。我们实践一下：

如果你已经对第四章的内容稔熟于胸，不难写出下面关于每组预测值（平均数）与回归系数之间的关系。

\[ \begin{align*} \hat{y}_{\text{机人+无灵根}} &= b_0 \\ \hat{y}_{\text{机人+有灵根}} &= b_0 + b_2 \\ \hat{y}_{\text{袋人+无灵根}} &= b_0 + b_1 \\ \hat{y}_{\text{袋人+有灵根}} &= b_0 + b_1 + b_2 + b_3 \end{align*} \]

接下来，我们还是解方程。不难得到：

\[ \begin{align*} b_0 &= \hat{y}_{\text{机人+无灵根}} \\ b_1 &= \hat{y}_{\text{袋人+无灵根}} - \hat{y}_{\text{机人+无灵根}} \\ b_2 &= \hat{y}_{\text{机人+有灵根}} - \hat{y}_{\text{机人+无灵根}} \\ b_3 &= \hat{y}_{\text{袋人+有灵根}} - \hat{y}_{\text{袋人+无灵根}} - \hat{y}_{\text{机人+有灵根}} + \hat{y}_{\text{机人+无灵根}} \end{align*} \]

我们的b1和b2对应的组均值之间的关系是什么呢？b1对应的是，无灵根条件下，机人和袋人之间的均值差异。b2对应的是，机人条件下，有灵根和无灵根之间的均值差异。这是我们的主效应吗？看上去并不是。

如果你还记得就在不久之前，我们提到过一个主效应模型。也就是在哑变量编码的情况下，不放入交互作用项的模型。换句话说，就是上面的编码表中，没有交互项那最后一列的情况。同样的，我们可以写出这个主效应模型的预测值与回归系数之间的关系：

\[ \begin{align*} \hat{y}_{\text{机人+无灵根}} &= b_0 \\ \hat{y}_{\text{机人+有灵根}} &= b_0 + b_2 \\ \hat{y}_{\text{袋人+无灵根}} &= b_0 + b_1 \\ \hat{y}_{\text{袋人+有灵根}} &= b_0 + b_1 + b_2 \end{align*} \]

这组公式，我们有三个未知数，却有四个方程，我们不妨用前三个方程计算，易得：

\[ \begin{align*} b_0 &= \hat{y}_{\text{机人+无灵根}} \\ b_1 &= \hat{y}_{\text{袋人+无灵根}} - \hat{y}_{\text{机人+无灵根}} \\ b_2 &= \hat{y}_{\text{机人+有灵根}} - \hat{y}_{\text{机人+无灵根}} \end{align*} \]

那么第四个方程怎么办呢，我们不妨把上面三个回归系数，代回最后一个式子，得到：

\[ \hat{y}_{\text{袋人+有灵根}}=\hat{y}_{\text{机人+无灵根}} + (\hat{y}_{\text{袋人+无灵根}} - \hat{y}_{\text{机人+无灵根}}) +(\hat{y}_{\text{机人+有灵根}} - \hat{y}_{\text{机人+无灵根}}) \tag{1}\]

显然，这个等式不是一定成立的。怎么理解呢？我们可以通过图来直观的感受一下。

这是我们之前绘制的折线图。b0是机人无灵根组的均值，我标示在了右下角，并且画了一根灰色虚线来表示它的均值水平。而上面等式的左边，是我们的袋人有灵根组的均值，我用图中上部的灰色虚线表示。要让等式相等，其实我们可以看作从b0这根起跑线出发，怎么能够到达袋人有灵根组均值的终点线。那么，后面的b1和b2代表什么呢？依照我们的推导，b1代表的是无灵根组的机人和袋人在魔法天赋上的差值，也就是图中旁边标示了b1的红色箭头；而b2代表的是机人组中，有灵根和无灵根在魔法天赋上的差异，也就是旁边标示了b2的蓝色箭头。那么，我们从b0出发，先跑过红色箭头表示的距离，再跑过蓝色箭头表示的距离，最终会准确抵达终点吗？显然，在图中的这种情况下是不会的，我们会跑过头非常多。

Type III

1. 必须修改对比方式 (Contrasts)

这是最关键的一步。R 默认的对比方式是 contr.treatment（处理对比），这会导致自变量之间不具有正交性，从而使 Type III 的计算失去统计学意义。

  • 要求： 必须将对比方式改为 contr.sum（总和对比）或 contr.helmert。

2. 正确的代码实现步骤

假设你的模型是 magic_score ~ iden * spirit_root，你应该按照以下流程操作：

library(car) # 第一步：在建立模型时，显式指定 contrasts # 这一步是为了确保截距项和主效应在存在交互作用时能被正确分割 model_type3 <- lm(magic_score ~ iden * spirit_root, data = df5.1, contrasts = list(iden = contr.sum, spirit_root = contr.sum)) # 第二步：使用 car::Anova 并指定 type = 3 result <- Anova(model_type3, type = 3) # 查看结果 print(result)}

简单来说：

  • contr.treatment = Dummy Coding（哑变量编码 / 参照编码）

  • contr.sum = Effect Coding（效应编码 / 偏差编码）

为了让你彻底看清这两者如何影响 Type III SS 的结果，我们可以对比一下它们的内部机制：

1. 哑变量编码 (Dummy Coding / contr.treatment)

这是 R 的默认设置。它会选定一个基准组（Reference Group，通常是字母顺序第一的组）。

  • 系数含义： 其他组与基准组之间的差值。

  • 为什么不适合 Type III： 在包含交互项的模型里，如果你使用 Dummy Coding，主效应的 \(F\) 检验其实是在检验“当另一个变量处于基准水平时，当前变量是否有影响”。这不符合 Type III 要求的“所有水平的平均影响”。

2. 效应编码 (Effect Coding / contr.sum)

它将各组的效应与**全体均值（Grand Mean）**进行比较。

  • 编码方式： 最后一组被编码为 -1，其他组编码为 1 或 0。

  • 系数含义： 该组均值偏离总均值的程度。

  • 为什么它是 Type III 的标配： 在 Effect Coding 下，各因素的列之间是**正交（Orthogonal）**的。只有这样，当你计算某个因素的平方和时，才能真正做到“剔除掉交互项和其他所有项的影响”，得到干净的主效应贡献。

The answer depends on whether your intention in a contrast is to treat means as having equal import regardless of group size (n), which is the unweighted means approach, or to weight means relative to their sample size, which of course, is a weighted means approach.

For an unweighted means approach, two contrasts are orthogonal if the sum of coefficient product terms, across groups, equals zero: e.g., c11c21 + c12c22 + … + c1kc2k = 0 (where cij is the coefficient used for the i-th contrast and j-th group).

For a weighted means approach, two contrasts are orthogonal if: n1c11c21 + n2c12c22 + … + nkc1kc2k = 0 (where cij is defined as above and nj is the sample size for group j).

In many experimental designs, the usual intention of behind a contrast is to compare means as having equal import regardless of group size. Therefore (using cij and nj as defined above):

SS(contrast i) = (ci1*M1 + ci2M2 + … + cikMk)^2 / (ci1^2/n1 + ci2^2/n2 + … + cik^2/nk) (where Mj is the mean for group j)

Here’s a link that walks through a worked example: https://www.uvm.edu/~statdhtx/StatPages/Unequal-ns/Unequal_n’s_contrasts.html

Finally, B. J. Winer’s 1971 text, Statistical principles in experimental design (2nd ed.). also addresses the issue.

对比编码

这是一个非常细致的问题。简单来说：contr.helmert 属于效应编码（Effect Coding）的一种大类，但它与 contr.sum 的具体逻辑完全不同。

如果说 contr.sum 是把每一组与“整体平均值”比，那么 contr.helmert 就是在做“阶梯式对比”。

1. contr.helmert 的核心逻辑：分层累积比较

Helmert 编码的特点是：将当前的水平（Level）与之前所有水平的平均值进行比较。

假设你的变量有三个水平：A、B、C。

  • 第一个对比： B vs. A

  • 第二个对比： C vs. (A 和 B 的平均值)

  • 第三个对比（如果有 D）： D vs. (A, B, C 的平均值)

2. 它与 contr.sum (Standard Effect Coding) 的区别

特性 contr.sum (偏差编码) contr.helmert (Helmert 编码)
比较基准 所有组的总平均值 (Grand Mean) 之前所有组的平均值
适用场景 想知道某一组是否偏离整体平均水平。 变量具有某种顺序或累积性质时（如受教育程度、实验处理的递进）。
正交性 正交（在各组样本量相等时） 完全正交（各组样本量相等时）
对 Type III 的支持 支持，是标准的 Type III 做法。 支持，因为它是正交编码，能正确分割平方和。

3. 为什么 Helmert 编码也支持 Type III？

之所以你在某些教材中看到 contr.helmert 也能配合 Type III SS 使用，是因为它满足了 正交性（Orthogonality） 的要求。

在方差分析中，只要编码是正交的，截距项、主效应和交互项对应的设计矩阵列就是相互独立的。这样，Type III SS 在剔除其他项的影响时，不会把属于该项的变异给“误杀”掉。

A -1 -1
B 1 -1
C 0 2

4. 什么时候用 contr.helmert 而不是 contr.sum？

虽然两者都能让 car::Anova(type = 3) 跑出正确的 \(F\) 检验和 \(P\) 值，但它们对**回归系数（Coefficients）**的解释完全不同：

  • 如果你关注整体偏离： 选 contr.sum。比如你想看“金灵根”是否比“平均水平”更强。

  • 如果你关注递进效果： 选 contr.helmert。比如你的自变量是“修炼等级”（初级、中级、高级），你想看“高级”是否比“初级和中级的平均水平”有显著质变。
